# G1 — Player in the World: первый игровой контур [GAME]

**Статус:** исполняемый vertical slice; не обещание законченной игры, не CANON.

## Что изменилось

Впервые управляемый персонаж **является настоящей сущностью ECS**, а не только Three.js-аватаром. Браузер предлагает выбрать James, Sirius, Remus или Peter. Один и только один из четырёх становится `ManuallyControlled` и исключается из автономного NPC-списка; остальные продолжают жизнь по собственному школьному расписанию. Lily всегда остаётся независимой NPC. Peter создаётся в экспериментальном микромире как отдельный контролируемый персонаж. Существующие James/Sirius/Remus сохраняют прожитую к моменту выбора лабораторную историю.

Архитектурный путь:

```text
WASD / touch → локальная анимация тела
UI passage → submit({type:'move',destination}) → world.execute({type:'move', actor: controlledEntity})
                                                        ↓
                                            ECS validation + entity_moved
                                                        ↓
                                            playerView().room → scene transition
```

Даже если клиент запросит несуществующий, несмежный или закрытый переход, ECS проверит факт доступа и вернёт отказ. Клиент не может подменить `actor` извне и управлять чужим NPC. `playerView()` возвращает только идентификатор персонажа, реальную комнату, известные ему выходы и локально доступные признаки предмета.

## Первое действие с последствиями — старая чашка

В гостиной есть отдельная ECS-сущность `fragileObject` — **старинная чашка**. Рядом с ней игрок может выбрать «Осмотреть» (`inspect_object`) или «Разбить» (`break_object`).

- Осмотр записывает личное наблюдение персонажа, а не глобальный тайный флаг клиента.
- Разбитие изменяет реальное состояние ECS-объекта, создаёт `WorldEvent`, меняет его внешний вид и не может быть повторено как новое разрушение.
- За пределами комнаты игрок не получает текущее состояние предмета через `playerView`.
- NPC сохраняют собственную автономию; новая сцена не прописывает отдельного эмоционального сценария для Джеймса/Лили при разбитии чашки.

Объект показан простой процедурной 3D-моделью, без сторонних ассетов.

## Важные незакрытые границы

1. **Это пока отдельная браузерная лаборатория на четырёх экспериментальных NPC, а не 634-персонажный серверный Хогвартс.** Нет общих миров между вкладками и постоянного сохранения при обновлении страницы.
2. Ручное хождение внутри комнаты по WASD остаётся клиентской геометрией. ECS хранит истинную комнату персонажа, **не непрерывные координаты**. Команды осмотра/разбития проверяют комнату на стороне мира; физическая дистанция до чашки пока задаётся UI. Не выдавать локальную близость за ECS-валидированный факт.
3. Переходы игрока между комнатами сейчас синхронные `move` команды. Полностью временное управляемое путешествие и checkpoint для движения — следующие задачи; NPC пользуются RB-5.1.
4. Открытая техническая панель башни всё ещё содержит известную разработчику геометрию. Это **debug** навигатор, а не знание игрока и не будущая Карта Мародёров.
5. Мир пока не делает содержательных выводов из разбития чашки для дисциплины, учёбы или сложных отношений. Предметное событие и доступные наблюдения — реальные; дальнейшие системы причинности предстоит подключить.
6. Модель кастинга допускает выбор одного из четырёх Мародёров. Семикурсники здесь — отладочный возраст, **не** готовая игровая кампания первого курса.

## Следующий игровой рубеж

**G2 — Player Perception + Context Actions.** Дать игроку настоящую локальную позицию и проверяемую дистанцию взаимодействия, отделить доступные/известные маршруты от debug-графа, добавить один предмет, который можно физически перенести или изучить, и только потом расширять школьную аудиторию. За основу взять `docs/game-design/architecture-to-playable-slice.md` из обсуждаемого дизайн-PR #65.

## Тесты и выходные критерии

- `client/tests/player-session.test.mjs`: четыре варианта персонажа, ручное управление, отсутствие клонирования, действительная топология, запреты, личные наблюдения и сломанный предмет, независимость NPC, защита от подмены actor.
- `client/tests/browser-smoke.mjs`: браузерный выбор персонажа, настоящий ECS-объект и фактическое сохранение эффекта внутри сессии, Three.js комнаты/движение, старый WASD/camera/geometry regression.
- `npm test` + `npm run build` + Chromium/WebGL smoke в CI.

**Впервые у игрока есть роль и последствия.** Полноценный school-life immersive sim появится тогда, когда эти личные действия соединятся с знаниями, расписанием и другими учениками без привилегий «главного героя».
