# Gryffindor Tower — client prototype 0.1

**[GAME]** Автономный, статический Three.js-клиент для GitHub Pages и
последующей интеграции в Telegram Mini App. Первое испытание:
**камера / трёхмерное пространство / управление / восемь ракурсов / переходы**.

## Архитектура

    authoritative Simulation (only at build)
       createSchoolWeek(research-600)
         └── graph node IDs, connections, live bedroom occupancy
              └── generator ── JSON manifest
                   └── static client HTML/CSS + Three.js
                        ├── cutaway 3D chamber
                        ├── 8 independently painted sprite textures
                        ├── camera-relative WASD + click-to-move
                        └── room transitions checked against graph edges

В браузере отсутствуют ECS, Node.js, API, authentication и server
simulation. Состояние прогулки временное и локальное.

## Принципиальные гарантии прототипа

- Полный список помещений извлекается из **того же**, а не повторённого
  построителя исследовательского графа: 37 спален на 150 жителей,
  2 устаревших узла, гостиная и связанный с ней landing.
- Любой переход между двумя различными комнатами проверяет
  \`graph.links\`: нет прямого прохода между разными спальнями.
- Лестницы — пока **интерфейс выбора групп спален** над star topology.
  Они не притворяются полноценными физическими коридорами ECS.
- Спрайт не просто billboard-поворот: у него восемь визуально
  различных текстур, а камера выбирает одну по относительному азимуту.
- Простые цилиндрические коллизии и клики на пол — **прототипный слой**,
  не результат физики серверного симулятора.
- Источники архитектуры и расхождения между книгами/графом:
  [research](../../research/gryffindor-tower-visual.md).

## Порядок подключения симуляции позже

1. Ввести отдельные \`SpatialPresentation\` и \`RoomLayout\` c физическими
   входными anchor-точками, не меняя \`EntityId\` и ссылки графа.
2. От сервера получать только наблюдаемое игроком состояние текущей комнаты:
   персонажей, доступные двери, объекты, наблюдаемые события.
3. Команды "переместиться / предложить встречу / применить заклинание"
   валидировать общей simulation, а клиент пусть интерполирует движение.
4. Продумать частоту тиков и интерполяцию времени: существующие 10
   игровых минут не представляют каждое движение внутри комнаты.
5. Только затем добавить полноценную навигацию по этажам и Telegram
   серверную интеграцию; первая версия полностью offline-compatible.

## GitHub Pages

Workflow \`.github/workflows/gryffindor-pages.yml\`:
PR = check/build без публикации;
main = check/build + Pages deploy, если разрешено настройками GitHub.
Сборка Vite: base \`/Marauders/\`. Адрес при успешной публикации:
\`https://cg13dev.github.io/Marauders/\`.

GitHub private-repository Pages может требовать оплачиваемый план
организации; **никогда не следует выдавать URL за рабочий без успешного
deployment**. Администратор может быть должен выбрать
**Settings → Pages → Source → GitHub Actions**.
Даже если репозиторий private, Pages-публикация может быть публичной.
