# G5.1 — Narrative Bridge (изолированный текстовый срез) [GAME]

**Статус:** PR-прототип. Использует существующий Node.js ECS `simulation`, без 3D и без отдельного «LLM-мира».

## Цель и границы

Один и тот же `createTextSession()` управляет перемещением, уроками, знаниями, памятью и сохранениями. `NarrativeBridge` добавляет **только** описания сцен и реплики собеседника. `NarrativeProvider` допускает `MockNarrativeProvider` и `OpenAINarrativeProvider`.

```text
ECS -> субъективное восприятие / знания -> NarrativeBridge -> Provider -> речь
действие игрока -> существующий TextSession -> ECS.execute -> мир
```

**Никакого:** исполнения действий LLM, изменения ECS через выдуманную речь, автоматического обучения, чтения чужих мыслей или передачи модели `events()` / `captureRuntime()`. Обещание встречи требует настоящих команд `offer_meeting` / `answer_meeting`; слова «обещаю» пока не создают обязательство.

## Расширенный локальный интерфейс (browser first)

Чтобы изучать возможности мира **без оплаты API**, запускай:

```bash
cd simulation
npm install
npm run narrative-web
```

Открой **http://127.0.0.1:4177/**. Сервер доступен только с собственного компьютера, без публикации в интернете. Порт можно менять переменной `MARAUDERS_TEXT_PORT`. Если сервер уже работает, останови его через Ctrl+C.

Это **не** WebGL-прототип и **не** новый игровой движок. HTML/CSS/JS отображают структурированную, личную проекцию состояния **того же** игрового ECS-сценария, который уже использует `npm run play`. Игрок видит: помещение и его [GAME] атмосферное описание; знакомые выходы; присутствующих лично видимых персонажей; настоящие локальные книги; знания Lumos/Wingardium; уроки, посещаемость и личные социальные воспоминания. Контекстные кнопки дают возможность переместиться, подождать, начать чтение, практиковать / применить Lumos, обратиться к собеседнику, поговорить об уроках, запросить обучение, пригласить к совместной учёбе. Игровые операции проходят существующие ECS-проверки, не становятся «правдой UI» при отказе.

Только явная команда **«Описать сцену»** обращается к рассказчику. Поле реплики **«Сказать»** использует адаптер отдельно от кнопок настоящих игровых действий. Переключение между ними принципиально: свободная речь пока не изменяет ECS, а `chat`, `offer`, `ask` используют настоящие команды. Перемещения и ожидание двигают школьные тики; сцена и произнесённая фраза в текущем G5.1 времени не потребляют.

Из браузера можно выгрузить checkpoint в JSON и восстановить его без доступа веб-клиента к файловой системе Node.js. История текстовых реплик не сохраняется; ECS-история сохраняется. Не редактируй загруженные checkpoint из недоверенного источника.

## Mock: что он действительно тестирует

Mock **не вызывает API** и **не генерирует свободный текст**. Раньше он возвращал почти константную фразу. Теперь это прозрачная детерминированная фикстура для реального сценария:

1. Игрок из гостиной доходит до класса чар (`go corridor`, `go classroom`).
2. Спрашивает Лили про **Люмос**, пока та его ещё не проходила: она отвечает в mock-режиме, что не изучала заклинание.
3. Проходит 20 игровых минут (`wait 2`). Если Лили действительно присутствовала на объяснении квалифицированного преподавателя, её ECS-знание становится `conceptual`.
4. Повторный вопрос о Люмос возвращает другой шаблонный ответ, соответствующий **реальному новому состоянию знания**.
5. Фразы о других темах честно получают заглушку. Mock не понимает произвольные формулировки, не изображает бесплатную LLM.

Тест проверяет именно связь «запрос → актуальная личная проекция → разный ответ при изменении ECS» и изоляцию игровой истины от генератора. Это **не** тест качества семантического диалога, характеров или галлюцинаций реальной модели. Отдельные HTTP/UI-тесты проверяют действия из браузера и отсутствие неявных платных запросов.

Реальный браузерный режим:

```bash
export OPENAI_API_KEY='...'
npm run narrative-web-live
```

Он делает **платный** API-вызов только при явном нажатии «Описать сцену» или отправке реплики. Для локального доступа и проверки контекстных интерфейсов лучше оставаться на `narrative-web`.

## Запуск

Node.js >=22.16.0:

```bash
cd simulation
npm install
npm run typecheck
npm test
npm run narrative-demo   # без сети, smoke
npm run narrative-play   # интерактивный mock, бесплатно
```

Команды: `scene` (описание лично воспринимаемого), `say lily Привет, Лили! Как дела с чарами?` (свободная речь с физически присутствующим NPC), `look`, `people`, `go corridor`, `go classroom`, `wait 1`, `chat lily lessons`, `status`, `save game.json`, `load game.json`. Игровые команды остаются в `text-game.ts`. Из гостиной Джеймсу нужно пройти коридор и добраться до класса, прежде чем разговаривать с Лили.

Реальный API — **только явный opt-in**:

```bash
export OPENAI_API_KEY='...'
npm run narrative-live
```

Ключ задаётся локально на сервере, не вносится в Git, браузер, конфиги или параметры CLI. `MARAUDERS_NARRATIVE_MODEL` задаёт модель (по умолчанию `gpt-6-luna`, `reasoning.effort=low`). Используется OpenAI Responses API, `store:false`, `max_output_tokens:500`, timeout 20 секунд, ограниченный контекст. Запросы делает только Node.js при явных командах `scene` и `say`. Никаких автоматических запросов от 600 NPC.

**Важно:** подписка ChatGPT не включает расход OpenAI API. Для `narrative-live` нужны отдельные API-доступ и оплата. Mock не требует ключа или сети.

## Персонажная перспектива

Построение `npcPerspective` требует совместного помещения и слуха обоих участников. Проекция содержит:

- личные заклинания, примитивы и происхождение последних этапов обучения;
- личные убеждения, наблюдения и историю разговоров / обязательств по отношению к игроку;
- **направленное** отношение NPC к игроку, школьное расписание;
- известные потребности (если моделируются) и явно настроенный `DailyLifePlan`;
- видимых персонажей, книги и магические предметы в текущей комнате;
- отдельно обозначенный авторский профиль речевого темперамента [GAME], **не** фактическую эмоцию.

Сцена получает только `scenePerspective(player)`: место, видимые сущности / книги / магические предметы, известные выходы и личные наблюдения. Без зрения герой **не** получает списки видимых персонажей и книг. Модель не получает глобальный `RuntimeSnapshot`, `WorldEvent`, скрытые гипотезы и знания других NPC. Контекст ограничен по объёму: это релевантная выборка, а не вся жизнь героя.

## Честные ограничения G5.1

1. **Диалог пока презентационный.** Реплики игрока и NPC живут в небольшом временном буфере `NarrativeBridge`, не являются фактами игрового мира, не тратят игровые минуты, не сохраняются в checkpoint. Для социального события есть отдельная команда `chat` и ECS. После `load` буфер очищается.
2. В ECS **нет общей модели настроения**: поле `currentMood` помечено «не моделируется», а не придумывается. Затем нужно строить причинный эмоциональный контекст из личной истории, потребностей и обязательств.
3. Промпт запрещает выдумывать мир, но **не гарантирует отсутствия галлюцинаций**. Повествовательный ответ не является доказательством факта. Строгой пост-валидации утверждений реплики пока нет.
4. Это существующий малый текстовый сценарий `createStarterSchool`, не мост к 600 NPC и не кооперативный сервер. Замок и 3D не затрагиваются.
5. Нет интерпретатора свободных **игровых действий**: `say` — только речь. Следующий срез добавит типизированный запрос `PlayerIntent` через `world.execute`, а не исполнение выводов LLM напрямую.

## Проверка

`simulation/tests/narrative-bridge.test.ts` запускается штатным `npm test`. Проверяет изоляцию личных знаний и отношений NPC; видимость без зрения; отказ в дистанционной/неслышимой беседе без вызова модели; неизменность ECS после сцены и разговора; ограничение истории реплик; формат HTTP-запроса к Responses API через подставной `fetch` **без сети**; обработку ошибок.

CI не совершает платных запросов и не зависит от OpenAI. Реальный API-smoke — только явный локальный запуск разработчика.
