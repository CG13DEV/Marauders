# Академическая магия — первый интеграционный срез

**Статус:** [GAME] исполняемый headless vertical slice / feature PR, без претензии на готовую систему семилетнего образования.  
**Связанные источники:** [Академическая модель](hogwarts-academic-model.md), [Spell learning](../game-design/spell-learning-and-curriculum.md), [Прогрессия](../game-design/progression.md), [Lore & Magic](../lore/lore-and-magic.md).

## Зачем

В симуляции уже существовали автономное школьное расписание, посещаемость, отдельная личная память о `lumos`, помощь однокурсников, практика и один исполняемый световой эффект. Но содержание учебной программы было частично зашито в генератор `school-week`, а реальная библиотека была только локацией — **не источником знаний**.

Этот срез связывает три реальные подсистемы: **время/посещаемость**, **физически доступный источник**, **личное освоение и исполнение заклинания**. Он не подменяет их отдельным RPG-экраном.

## Сценарий [GAME]

1. Профессор и Лили находятся в классе чар. Ремус находится в библиотеке и сознательно пропускает урок.
2. `introductorySpellFor(1,'Charms')` назначает **конкретному занятию** пробный учебный материал `lumos`. Это GAME-реконструкция эпохи 1970-х; не каноническое распределение программы.
3. Лили, **физически присутствующая** на уроке в момент объяснения, получает `conceptual`; отсутствующий ученик сохраняет `unaware` и реальный пропуск.
4. В библиотеке стоит именованный физический учебник, созданный через `world.spellBook(key,title,room,spell)`. `world.visibleBooks(actor)` показывает только **обложку локально видимой книги**, но не её скрытое содержимое или данные удалённых шкафов.
5. Ученик начинает действие `study_book`, остаётся рядом с книгой **20 игровых минут** (два школьных тика), и лишь по завершении получает `conceptual` с источником `{kind:'library',book,minute}`. Пока чтение не окончено — магия не разблокируется. Перемещение или текущий урок прерывают чтение.
6. Чтение **не даёт** `guided` и `independent`. Ученик должен практиковаться по существующим правилам: квалифицированный наставник рядом для первой практики, затем самостоятельное исполнение.
7. Книга, личная история обучения и незавершённое чтение сохраняются в **journal replay** и **materialized checkpoint**, с безопасной перенумерацией ECS entity IDs.

События: `book_reading_started`, `book_reading_interrupted`, `book_read`, `spell_concept_learned(source:library)`. Записи формируются **авторитетным миром**. Наблюдение книги не создаёт магического знания, а внутренние знания одного ученика не распространяются автоматически.

## Архитектура

```text
curriculum unit (year + subject + spell)
             │
             ▼
teacher + room + scheduled lesson ───────┐
             │                            │
     physical attendance                  │
             │                            │
             ▼                            ▼
     CharacterSpellKnowledge ◄──── physical spell book
             │                   │     + reading session
             │                   └── personal library provenance
             ▼
  guided practice / independent cast
             │
             ▼
  same world-authoritative magic effect
```

**Разделение ответственности:** `curriculum.ts` хранит учебные назначения; `school-week.ts` производит уроки с расписанием; `Simulation.ts` отвечает за физическую достижимость, время, реальные события и влияние на мир; `spellcraft.ts` — за личные стадии знания и provenance; `persistence.ts` — за сохранения. Никакой LLM не назначает физический эффект и не изменяет authoritative state.

**Инварианты:** отсутствующий ученик не получает концепцию от урока; удалённая книга не читается; прочтение не превращается в самостоятельное колдовство; завершение исследования без физического времени запрещено; прерывание занятия не выдаёт знания; восстановление не дублирует успешное чтение.

## Запуск и проверки

Из `simulation/`:

```sh
npm run academic-magic-demo
npm test
npm run typecheck
```

Тесты `tests/academic-magic.test.ts` покрывают присутствие и пропуск, доступность книги, глаза/локальность, два тика чтения, прерывание, единую цепочку практики, journal replay и checkpoint.

## Что **ещё не реализовано**

- Полное распределение заклинаний по **семи годам**: сейчас для демонстрации привязан **один** [GAME] unit `lumos` к первому курсу чар. Таблица `SPELL_TEACHING_UNITS` — точка расширения, а не утверждение о каноне.
- Автономный **выбор книги и поход NPC в библиотеку**: NPC продолжают по расписанию учиться и помогать друг другу; библиотечное действие пока инициируется вручную. Следующий вертикальный срез должен добавить планирование по личной нехватке знаний с проверкой времени, маршрута, альтернативы уроку и доступности книги **без глобального знания содержимого библиотеки**.
- Живое движение чтения как *субтиковое* действие для графического клиента, бронирование стола, книговыдача, Запретная секция, усталость и межученическая конкуренция за экземпляры.
- Магическая функция для `Wingardium Leviosa`, функциональные траектории, реальный `spell graph` и реверс-инжиниринг — пока **дизайн**, не исполняемый редактор.
- Реальная игровая UI-интеграция клиента с headless world. Текущий результат демонстрируется через CLI и автоматизированные тесты.

## G4.1 — автономная библиотека и практика [GAME]

**Исполняемый opt-in срез:** `createAutonomousAcademicMagicSlice`, `npm run autonomous-academic-magic-demo`, `tests/autonomous-academic-magic.test.ts`. Сценарий начинается с **реально пропущенного** занятия: первоначальное ручное управление лишь формирует исходное отсутствие; после окончания урока Ремус действует уже без команд игрока.

- **Мотивация:** существующий `knowledgeGaps` создаёт личный `learn_concept` intention. Цель остаётся внутри `intentionPlanning` и `chooseNeedOrIntention`: уроки, еда, усталость и обязательства важнее бесконечной гонки к знаниям.
- **Выбор пути:** если разрешены социальные приглашения и рядом есть допустимый собеседник, используется прежняя система учебных встреч. Если нет — ученик может направиться в **лично известную** библиотеку из `DailyLifePlan.libraryRoom`. Это не глобальный указатель на книги и не повсеместное знание содержимого шкафа.
- **Обнаружение книги:** `visibleBooks(actor)` возвращает **только обложки в той же комнате**; `chooseLocalStudyBook` ориентируется на явное название формулы на обложке. Если такого текста нет, персонаж пока **не способен определить релевантность** (для этого впоследствии нужен каталог / пролистывание / разговор). Не используется закрытое `books.get(bookId)` для выбора.
- **Физическое действие:** `travelTo` двигает ученика по реальным проходам и валидирует дверные условия. В библиотеке NPC запускает тот же `study_book`, что и игрок, занимает 20 игровых минут; другие действия не выполняются одновременно.
- **От теории к практике:** в следующий досуг ученик может попросить **физически присутствующего и согласного помогать** персонажа о практической тренировке. Проверка истинной квалификации производится только в `practice_spell` авторитетного мира. Неудачные попытки запоминаются. После guided-стадии существует прежний `setExperimenter` для самостоятельной практики.

**Границы:** `libraryRoom` — изначально известное самому персонажу место (например, из ориентации в Хогвартсе), а не автоматически раскрываемая сцена. Пока нет поиска литературы по каталогу, обмена сведениями о местоположении и намеренного выбора книги по содержимому после просмотра страниц. Преподаватель в тестовом сценарии движется в библиотеку по реальному `setRoutine`; полноценных расписаний факультативных консультаций ещё нет. Учебный `Lumos` на первом курсе — по-прежнему [GAME], а не исторически доказанное содержимое программы 1970-х.

**Принцип:** знание об источнике не тождественно владению заклинанием; мотив поиска должен быть личным, источник доступным, путь физическим, эксперимент ограниченным временем, практика самостоятельной, события — персистентными. Существующие `School Planner`, `Intentions`, `World.execute` и `SpellKnowledge` являются единым контуром.

## Следующий маленький шаг

Расширить личный поиск информации без прямого названия формулы на обложке: каталог, реальные сведения от знакомых, физический просмотр книги и запоминание её местоположения. Затем добавить самостоятельный выбор NPC между библиотекой и живой консультацией в зависимости от занятости, доступности и доверия. После этого — связывать изученные магические примитивы с настоящим spell graph и реверс-инжинирингом.
