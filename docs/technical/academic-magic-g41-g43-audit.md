# Архитектурная ревизия: G4.1 → G4.2 → G4.3

**[GAME]** Проверка интеграционных границ после слияния G4.2 и перед вводом G4.3 в `main`. Исходный код симуляции — источник истины; здесь отделены **реальные контракты** от отдельных демонстрационных сценариев.

## Сквозной маршрут данных (уже работает)

| Шаг | Реализация | Что хранится |
| --- | --- | --- |
| Посещение занятий | `school-time.ts` + фаза обучения `scheduler.ts` | расписание, личная посещаемость, lesson provenance |
| Восполнение пропуска | `DailyLifePlan.libraryRoom`, `chooseLocalStudyBook`, `study_book` | локальные видимые обложки, физическое чтение 20 минут, личное `SpellStage` |
| Готовая формула | `spellcraft.ts`, `practice_spell`, `cast_spell` | стадии conceptual / guided / independent |
| Основы магии | `Lesson.primitive`, `knownMagicPrimitives` | отдельно известные `position_lock`, `force_feedback`, `light_emission` |
| Физическое исполнение | `MagicPattern`, `magic-graph.ts`, `magicObject` | материальная позиция, скорость, свет и активное воздействие |
| Исследование | `magic-research.ts` и `Simulation.execute` | личная гипотеза, конкретная проба, до/после, неполный опыт |
| Персистентность | `persistence.ts`, `runtime-snapshot.ts` | replay/checkpoint: личные знания, объекты, ссылки и наблюдения |

Всё исполняется **одним игровым миром** с едиными абсолютными минутами и проверкой физических действий в `Simulation.execute`. G4.2 и G4.3 не создают самостоятельную вторую симуляцию поверх ECS. Для всех трёх этапов есть сценарии и тесты; они проверяют поведение головного движка, а не только конфигурационный файл.

## Что пока НЕ склеено в реальном Хогвартсе

1. **Учебная программа.** В общей `createSchoolWeek(...,'library-g4-1')` пока размещается библиотечный `Lumos` первокурсников. Уроки `Wingardium Leviosa` и отдельные уроки магических примитивов живут в `createFunctionalMagicSlice`, а не в общей синтетической неделе 84/600 персонажей. **Срезы связаны движком, но ещё не общей школьной программой.**
2. **Автономная практика физического заклинания.** Фаза `experimental` в `scheduler.ts` вызывает `practice_spell` без `object`, что достаточно для `Lumos`, но **не для левитации G4.2**. Чтобы NPC тренировался с пером сам, ему нужен лично обнаруженный доступный объект и его выбор как цели. Пока левитационные опыты идут из явных команд в лабораторной фикстуре.
3. **Автономный научный метод.** `G4.3` записывает гипотезы, физические эксперименты и сравнения, но NPC не получает автоматически генератор гипотез, стратегию опытов и расписание лабораторной практики. Это важно: **личный журнал ≠ автономный исследователь**.
4. **Базовый эксперимент с именованной формулой.** Пока сравниваются две авторские реализации, но нет общего протокола «исходная формула при тех же внешних условиях → результаты кандидатного графа». Такой протокол нужен, чтобы гипотезы реально *объясняли наблюдаемый чёрный ящик*, а не только отличались друг от друга.
5. **Книги и социальные знания о примитивах.** G4.1 знает книги с готовой формулой; отдельные магические примитивы пока передаются явно на уроке G4.2. Поиск рукописей, исследование неизвестных операций, учебные подсказки других учеников не реализованы.
6. **Точная динамика клиентского мира.** Магические объекты пока рассчитываются раз за десять игровых минут в headless, это не физические кадры браузерного WebGL. Нужен согласованный мост дискретных причинных событий и плавной презентации, а не второй авторитетный physics engine.
7. **Разграничение доступов.** Внутренний `magicHypotheses(actor)` API читает журнал по ID для тестов и сохранений; внешние интерфейсы и NPC-политики должны вызывать его только для **своего** персонажа. Реальной системы обмена исследовательскими заметками через предметы/разговоры пока нет.

## Контракты, которые нельзя нарушить на следующих этапах

- Никто не узнаёт удалённую книгу, автора заклинания или чужую гипотезу через всемирный список объектов.
- Ученик не получает знание примитива от одного факта применения `Wingardium Leviosa` и не получает оригинальный граф из **совпадения результатов**.
- Физический предмет, время, расстояние, учитель, подготовка и проверяемые последствия должны оставаться источниками обучения — не виртуальные награды.
- Авторитетное состояние живёт в ECS + общем magic runtime; пути, графы, экспериментальные заметки сериализуются **как данные**, не через JS-код пользователя.
- `G4.1` ограничивает чтение физической доступностью. `G4.2` ограничивает сочинение графа **лично изученными** блоками. `G4.3` ограничивает эксперимент **наблюдаемым** и проведённым событием. Это разные, совместимые уровни знания.

## Предлагаемая последовательность интеграционных работ

**Следующий вертикальный этап:** добавить конкретное перо и учебный `Wingardium Leviosa` в opt-in полную школьную неделю, сделать **автономный выбор физической цели** для подготовки и эксперимента и сравнение с baseline готовой формулы. После этого — библиотечные сведения о примитивах, научные разговоры, инициативные испытания с учётом школьных обязательств.

Пока целостность **ядра** G4.1–G4.3 подтверждают тесты; целостность *автономного жизненного цикла «прогулял урок → изучил примитив → разработал заклинание» для полного населения замка* является **открытой интеграционной задачей**, а не закрытой фичей.
