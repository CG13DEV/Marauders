# AGENTS.md

Правила работы AI-агентов с репозиторием Maradeurs.

## Source of truth

GitHub — основной изменяемый источник истины для проектной документации.

Перед изменением документа:
1. прочитать его актуальную версию из репозитория;
2. прочитать связанные документы;
3. проверить, не дублируется ли информация в другом месте;
4. изменить существующий документ вместо создания новой версии файла.

Не создавать копии с суффиксами v2, final, final2 и подобными. История хранится Git.

## Lore classification

Каждое существенное утверждение о мире Harry Potter маркировать одним из уровней:

- **[CANON]** — прямо подтверждено книгами или официальными материалами;
- **[INFERENCE]** — естественный вывод из нескольких подтверждённых фактов;
- **[HYPOTHESIS]** — наша рабочая интерпретация там, где канон молчит;
- **[GAME]** — авторское решение игры.

Никогда не повышать HYPOTHESIS или GAME до CANON без источника.

Если факт спорный или источник слабый — явно это отметить.

## Design rule

Главный принцип:

> Мир задаёт правила. Игрок находит решение.

Предпочитать системные механики scripted-case решениям.

Хорошая механика должна:
- быть объяснима через общие правила мира;
- работать на неожиданных целях;
- порождать последствия;
- взаимодействовать с другими системами;
- сохранять состояние, если событие значимо для истории мира.

## AI architecture rule

LLM / semantic AI не должен самостоятельно симулировать физический мир.

Предпочтительный поток:

player intent / world event
→ semantic interpretation
→ rule validation
→ deterministic game systems
→ persistent world consequence

Физику считает физический движок, навигацию — навигационная система, gameplay state — игровые системы.

## Asset provenance rule

Сторонние материалы, используемые в приватной разработке, не считать автоматически пригодными для публичного релиза.

Для каждого важного стороннего ассета или референса фиксировать:
- источник;
- автора / правообладателя, если известен;
- заявленную лицензию или отсутствие ясной лицензии;
- роль в проекте: reference / prototype / temporary / production candidate;
- возможность замены;
- release risk.

Предпочитать архитектуру, в которой критические системы и геометрия не завязаны навсегда на один сторонний ресурс.

Перед любым публичным релизом проводить отдельный asset/IP audit.

Это рабочая production-политика, а не юридическое заключение.

## Documentation style

- Писать компактно и технически.
- Отделять подтверждённый лор от дизайна.
- Не придумывать псевдофизику, если она ничего не даёт gameplay.
- Сохранять сказочную неопределённость там, где она полезна.
- При новом решении обновлять связанные документы и ссылки.
